# Deal Radar

Мониторит авиабилеты из Москвы по всему миру и поезда по России. Когда цена падает
заметно ниже обычной для этого направления — присылает в Telegram не просто «дёшево»,
а готовый маршрут: перелёт, виза, жильё, план по дням, полный бюджет и ссылки на покупку.

---

## Быстрый старт

```bash
cd ~/deal-radar && ./dealradar setup
```

Мастер спросит два токена (как их получить — ниже), проверит связь и пришлёт тестовое
сообщение в Telegram. Дальше:

```bash
cd ~/deal-radar && ./dealradar start
```

Радар уходит в фон и включается сам при каждом входе в систему.

### Где взять токены

**Telegram-бот** (1 минута)
1. Открой в Telegram [@BotFather](https://t.me/BotFather)
2. `/newbot` → любое имя → любой username, оканчивающийся на `bot`
3. Скопируй токен вида `1234567890:AAH...`
4. Напиши своему новому боту `/start` — это нужно, чтобы он мог тебе писать

**Travelpayouts** (3 минуты, бесплатно) — источник цен на авиабилеты
1. Регистрация на [travelpayouts.com](https://www.travelpayouts.com/)
2. Раздел «Инструменты» → «API» → скопировать токен

Поезда работают без всяких токенов — данные берутся напрямую с `pass.rzd.ru`.

## Команды

```bash
./dealradar setup      # токены и проверка связи
./dealradar start      # запустить в фоне + автозапуск
./dealradar stop       # остановить
./dealradar restart    # перезапустить после правок config.yaml
./dealradar status     # работает ли, что нашёл
./dealradar doctor     # проверить все источники данных
./dealradar logs       # живой лог
./dealradar once       # один проход поиска прямо сейчас
./dealradar selftest   # проверить логику без сети
```

В самом Telegram: `/status`, `/find`, `/scan`, `/last`, `/threshold 50`, `/maxprice 40000`,
`/budget 6000`, `/shapes`, `/visa TH`, `/addtrain Москва - Тюмень`, `/pause`, `/resume`, `/help`.

## Как решается, что цена «супер-низкая»

Не по абсолютной цифре — по отклонению от нормы для конкретного направления.

1. **Норма.** Первые пару недель — стартовая таблица `data/baselines.json`.
   Как только по маршруту накопится 20+ собственных наблюдений, норма считается как
   медиана реально виденных цен. Дальше точность только растёт.
2. **Порог.** По умолчанию — дешевле нормы на **70 %** (авиа) и 50 % (поезда).
   Порог жёсткий: уведомления редкие, несколько раз в месяц, зато каждое — реальный
   повод бросить всё и лететь. Смягчить: `/threshold 55`.
3. **Санитарный потолок по дальности.** Страховка от кривой базовой цены, не главный
   фильтр: Стамбул дороже 20 000 ₽ не пройдёт, даже если формально это скидка. При
   выдающейся скидке (от 55 %) потолок растягивается в 1,6 раза — иначе Буэнос-Айрес
   за 62 000 ₽ вместо обычных 160 000 ₽ был бы отброшен из-за большой абсолютной цифры.
4. **Твой твёрдый потолок.** `/maxprice 40000` — выше этой суммы не придёт ничего,
   какой бы выгодной ни была скидка. По умолчанию выключен.
5. **Список желаний.** Для стран из `wishlist_countries` порог ниже на 7 п.п.

Незнакомые направления (которых нет в `data/cities.json`) присылаются только при
цене вдвое ниже потолка и с честной пометкой, что маршрут спланировать не смогу.

## Форматы поездок

Уведомление придёт, только если даты билета складываются в осмысленную поездку.

| Формат | Ночей | Условия |
|---|---|---|
| Длинные выходные | 3–4 | вылет чт после 16:00 или пт до 11:00, назад вс после 15:00 — **1 день отпуска** |
| Стандартный отпуск | 5–9 | считается, сколько рабочих дней съест |
| Длинная поездка | 8–25 | |
| Зимовка | 25–180 | только страны, где реально легально жить долго |
| Мультимаршрут | 8–25 | 2–3 страны, минимум 3 ночи в каждой |

Всё настраивается в `config.yaml` → `trip_shapes`, включать/выключать можно из чата:
`/shapes weekend off`.

## Что попадает в уведомление

Приходит короткая карточка — всё, что нужно, чтобы за десять секунд решить «беру или нет»:

```
🔥 Москва → Бангкок → Москва
СТАНДАРТНЫЙ ОТПУСК
📅 21.09 – 28.09 · 7 ночей · отпуска 5 дней

✈️ Билеты 18 000 ₽   65 000 ₽   −72 %
🏨 Жильё ≈ 6 500 ₽/ночь → 45 500 ₽
🧮 Вся поездка ≈ 87 296 ₽

🛫 Туда 21.09 в 13:40, 13 ч
🛬 Назад 28.09 в 23:10, 13 ч
🔁 1 пересадка ~11 ч — хватит выйти в город
🛩 Turkish Airlines — парк Boeing/Airbus
🧳 ручная кладь включена, багаж включён
🟢 виза не нужна, до 60 дней
🌤 сезон подходящий

🔗 Aviasales · Skyscanner · Туту · Google Flights
/details — весь маршрут с планом по дням
```

Категория поездки — первой строкой заглавными: **ТРИП ВЫХОДНОГО ДНЯ**,
**СТАНДАРТНЫЙ ОТПУСК**, **ДЛИТЕЛЬНОЕ ПРОЖИВАНИЕ** или **СЛОЖНЫЙ МАРШРУТ**.
Бизнес-класс помечается отдельно.

Команда `/details` разворачивает полный вариант: визовая карточка целиком (документы,
сроки, продление, работают ли карты), трансфер из аэропорта с ценами, районы для жилья,
план по дням и разбивка бюджета по статьям.

Жильё показывается **только ориентиром по цене** — уровень хорошего эстетичного жилья
с trip.com, без ссылок на агрегаторы (бронирование через туроператоров или trip.com).
Значения — в `data/hotel_nice.json`, правь под себя.

Если виза физически не успевает оформиться к дате вылета или поездка не помещается в
разрешённый срок пребывания — вариант **не присылается** вообще.

## Настройка под себя

Всё важное — в `config.yaml`, с комментариями. Самое полезное:

```yaml
traveller:
  max_vacation_days: 10      # максимум отпускных дней за раз
  max_stops: 1               # пересадок в одну сторону
  nightly_budget: 4500       # потолок за ночь жилья
  has_schengen_visa: false   # если появится — поставь true, шенген перестанет блокировать
  passport_valid_until: null # "2030-05-01" — предупредит про правило 6 месяцев

general:
  scan_interval_minutes: 45  # как часто проверять
  max_alerts_per_day: 12     # чтобы не спамило
  quiet_hours: [0, 8]        # ночью копит, но не будит
```

После правок: `./dealradar restart`.

Добавить ж/д маршрут: `/addtrain Москва - Тюмень` прямо в чате.
Свои визовые данные и города — `data/visa_rf.json` и `data/cities.json`.

## Потолок бюджета

Считается по **полной стоимости поездки**, а не по цене билета: билеты + жильё +
еда + виза + транспорт + страховка + запас. Дороже — уведомление не приходит.

| Формат | Потолок |
|---|---|
| Трип выходного дня | 50 000 ₽ |
| Полноценный отпуск | 100 000 ₽ |
| Длинная поездка | 150 000 ₽ |
| Сложный маршрут | 200 000 ₽ |
| Длительное проживание | без потолка |

Менять из чата: `/cap vacation 120000`, снять: `/cap multi_city off`, посмотреть
все: `/cap`.

Учти следствие: при жилье уровня trip.com неделя в дорогом городе сама по себе
съедает 50–70 тыс., так что в потолок 100 000 ₽ пролезут только направления с
недорогим жильём или очень дешёвым билетом. Это работает как задумано — если
находок станет слишком мало, подними потолок или снизь `hotel_nice` для нужных
городов.

## Сложный маршрут

Отдельная категория. Строится как Москва → страна A → страна B → Москва, минимум
3 ночи в каждой стране. Выгода считается честно: во сколько обошлись бы **две
отдельные поездки** туда-обратно в те же страны.

```
🔥 Москва → Буэнос-Айрес → Сантьяго → Москва
СЛОЖНЫЙ МАРШРУТ
📅 08.10 – 22.10 · 14 ночей · 2 страны

1. 08.10 Москва → Буэнос-Айрес — 52 000 ₽
2. 15.10 Буэнос-Айрес → Сантьяго — 12 000 ₽
3. 22.10 Сантьяго → Москва — 58 000 ₽

✈️ Все перелёты 122 000 ₽
📉 Отдельными поездками — 335 000 ₽, экономия 64 %
🏨 Жильё ≈ 119 000 ₽ за 14 ночей
🧮 Вся поездка ≈ 313 836 ₽
Буэнос-Айрес: 🟢 виза не нужна, до 90 дней
Сантьяго: 🟢 виза не нужна, до 90 дней
```

## Сторож процессов

macOS не даёт одному пользователю больше ~1333 процессов. Приложения, которые
запускают дочерние процессы и не убирают их за собой, копят «зомби»: памяти и
процессора те не едят, но занимают слоты. Когда слоты кончаются, перестают
запускаться терминал и новые программы — ошибка
`fork: Resource temporarily unavailable`.

Раз в 5 минут проверяется счётчик. На 300 зомби приходит уведомление в Telegram
с именем виновника. Чужие зомби убираются только завершением их родителя,
поэтому лечение — закрыть и открыть заново то приложение:

```bash
cd ~/deal-radar && ./dealradar cleanup
```

Команда найдёт виновника, покажет его и спросит подтверждение. Сам сторож ничего
не закрывает — решение всегда за тобой.

## Что считается удобным рейсом

Настраивается в `config.yaml` → `comfort`. По умолчанию отбрасываются:

- вылеты вне окна 06:00–23:00 — ночные рейсы в 4 утра не приходят;
- рейсы авиакомпаний, летающих только на Superjet (Азимут); у Аэрофлота,
  «России», Red Wings, «Ямала» и «Якутии» ставится пометка «возможен Superjet»;
- тарифы без ручной клади;
- направления не в сезон — Дубай в июле не придёт, даже если он дешёвый
  (исключение — скидка выше 85 %, задаётся в `season_override_discount`).

Пересадки оцениваются по качеству: прямой рейс лучше всего, короткая стыковка
(до 4 ч) нормально, длинная (от 8 ч) отмечается как возможность выйти в город,
а промежуточные 4–8 часов помечаются как неудобные — и не погуляешь, и высидишь.

**Важное ограничение по данным.** Авиа-API отдаёт только число пересадок и общую
длительность плеча — ни города стыковки, ни точного типа борта в нём нет.
Поэтому длительность стыковки вычисляется как «общее время в пути минус
расчётное лётное время» (формула сверена по реальным рейсам с точностью до
десяти минут), а самолёт определяется по парку авиакомпании, а не по конкретному
рейсу. Всё, что является оценкой, помечено словом «вероятно».

## Почему цена может не совпасть

Широкие ручки агрегатора отдают **кешированные снимки** цен — иногда суточной
давности. Именно из-за этого цифра в уведомлении расходилась с реальной ценой.
Теперь перед отправкой цена перепроверяется отдельным свежим запросом на
конкретные даты, а если после проверки скидка перестаёт проходить порог —
уведомление не отправляется вообще.

Даже так расхождение с площадкой в 10–20 % — норма: тарифы меняются в течение
минут, и разные агентства показывают разные наборы тарифов. Поэтому в каждом
уведомлении четыре ссылки — **Aviasales, Skyscanner, Туту и Google Flights** —
на одни и те же даты, чтобы сравнить в один тап.

Программно опрашивается один источник (Travelpayouts, он же данные Aviasales) —
у остальных площадок нет открытого API для запроса цен.

## Ограничения, о которых честно

- **Ноутбук должен не спать.** launchd поднимает радар при входе в систему, но пока
  Mac спит, проверки не идут. Если нужен режим 24/7 — код без изменений переносится
  на любой сервер или Raspberry Pi.
- **Визовая база — справочная.** Данные собраны на август 2026 и меняются быстро.
  В каждой карточке есть ссылка на официальный источник — сверяйся перед покупкой.
- **Цены живут минутами.** Особенно ошибочные тарифы. Уведомление — сигнал проверить
  ссылку сразу, а не через час.
- **`pass.rzd.ru` блокирует зарубежные IP.** Если пользуешься VPN, поезда могут
  отвалиться — `./dealradar doctor` покажет это прямым текстом, авиабилеты продолжат
  работать.
- **Бюджеты по городам — оценки** порядка величины, а не котировки.

## Как устроено

```
radar/
  main.py       запуск, два фоновых цикла: сканер и бот
  scanner.py    обход направлений, отбор кандидатов, отправка
  baseline.py   что считать нормальной ценой и что аномалией
  planner.py    сборка маршрута: формат поездки, дни, бюджет, ссылки
  visa.py       визовые правила для гражданки РФ
  flights.py    Travelpayouts (Aviasales) API
  rails.py      pass.rzd.ru, двухшаговый протокол с RID
  bot.py        команды в Telegram
  notifier.py   отправка сообщений
  storage.py    SQLite: наблюдения, отправленное, настройки
  doctor.py     диагностика источников
data/
  cities.json      76 городов: транспорт, районы, цены, сезоны, советы
  visa_rf.json     102 страны: режим, сроки, стоимость, документы, карты
  baselines.json   стартовые нормальные цены
  rail_routes.json 59 ж/д маршрутов
```

Состояние — в `dealradar.sqlite3`, логи — в `logs/`, секреты — в `.env` (права 600).
